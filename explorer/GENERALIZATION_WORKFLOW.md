# Explorer Generalization Workflow

> Runbook and requirements for making every Explorer mode as data-driven and
> subject-switchable as the Architecture mode is today.
>
> See also: [`EXPLORER_DESIGN.md`](EXPLORER_DESIGN.md) for the Observatory design language, and
> [`IMPLEMENTATION_GUIDE.md`](IMPLEMENTATION_GUIDE.md) for the end-to-end builder's manual (the
> diagram layout/no-overflow/containment algorithms + aesthetics). This is the **requirements**
> doc of that triad.

---

## 1. Purpose and UX Review Summary

The Explorer has three modes — **Data**, **Component**, and **Architecture** — housed in a
family-switcher shell. Of these, only Architecture is currently fully data-driven and
subject-switchable: its manifests are generated by `scripts/build_model_arch.py`, stored as
static JSON, consumed by a generic `ModelCircuit` renderer, and the model switcher lets the
user flip between Qwen3-0.6B, Qwen3-8B, Qwen3-30B-A3B (MoE), and DeepSeek-V3 (MLA-MoE)
without any component changes. This workflow makes that pattern the Explorer-wide standard:
Data gains a dataset switcher (FineWeb-edu → other corpora), Component gains a subsystem-graph
switcher, and shared UX primitives (subject switcher, detail drawer, toolbar, async boundary)
are extracted into a common kit so each mode is a pure consumer of its manifest, not a bespoke
one-off front-end.

## 2. Requirements (R1–R8)

### R1 — No text overflow (structural) + succinct block text

**Rule.** Box widths are NEVER hard-coded. They are computed per-manifest from monospace text
length using `width = chars × fontSize × ADV` (ADV ≈ 0.62, Fira Code 600-weight advance in
viewBox units). `cardWidth(label, kindTag, worstMetric)` measures the worst of the
label+tag line and the widest lens metric (shapes / compute / memory), adds
`PAD_L + PAD_R + TAG_GAP + COMFORT`, and takes the max over all blocks in the manifest.
Mainline boxes (`MAIN_W`) and branch-panel boxes (`CARD_W`) are computed independently; floors
are enforced (`MAIN_W_MIN=180`, `CARD_W_MIN=240`). `MAINLINE_X`, `CARD_X`, `SHELL_LEFT/RIGHT`,
and `VIEW_W` all derive from these measured widths. See the top-of-file INVARIANT comment in
[`src/architecture/ModelCircuit.tsx`](src/architecture/ModelCircuit.tsx).

The worst metric is measured across a **geometric sweep of token counts over `[8, MAX_TOKENS]`**,
not only at `MAX_TOKENS` — the longest metric *string* can occur at a mid token count (e.g.
`KV 999.9 KiB` is wider than `KV 4.5 MiB`), so boxes fit at every slider position.

**Containment hierarchy (outline ⊇ panels ⊇ text).** Layer-group outlines are derived from the
real branch-panel extents (topmost header-pill top → bottommost tee dot, + `BRACKET_M`), and
groups are placed along a running `cursor` so adjacent outlines/chips never overlap (`GROUP_GAP`).
This makes the full hierarchy — group-outline contains block-panels contains box-text — enforced
by construction, not by manual tuning.

**Succinct block text.** Block labels must be terse (target ≤ ~22 chars; hard ceiling 24).
Prefer the short symbol form — e.g. `Q down-proj (A)`, `MLA attention`, `QKV projection`.
Full prose belongs in the `desc` (and `note`) fields rendered in the detail drawer, never on
the block face.

**Acceptance check.**
- Computed `cardWidth(label, kind, worstMetric)` ≥ measured text for every block in every
  manifest; no label exceeds 24 chars.
- Run: `python explorer/scripts/build_model_arch.py && python - <<'EOF' ... EOF`
  (no-overflow audit; see Verification Checklist §5).

### R2 — Strong aesthetics

**Rule.** Observatory glass kit: kind-tinted gradient card fills (`url(#grad-<kind>)`), kind
tags, slim accent bar (3 px left edge), rounded-elbow wiring (`roundedOrthPath`, r=12), gradient
mainline (`rail-grad` indigo→cyan) + animated flow ticks, cyan selection glow (`stroke=#38bdf8`,
`strokeWidth=2`), tinted branch panels (`fillOpacity=0.05`) with header pills, comfort margins
(`COMFORT=16`, `PAD_L/R`, `PRENORM_GAP`), body-text scale (label 12 px mono 600, metric 9 px
mono, kind tag 7.5 px), `maxWidth`-capped SVG, dark-only (`color-scheme: dark`).

**Acceptance check.** Visual checklist: dark void + radial gradient; fonts (Inter prose, Fira
Code mono); kind colors differentiated; selection glow visible; branch panels tinted. All new
views reuse `KIND_COLOR`, `grad-<kind>` defs, and the `.panel`/`.diagram-*`/`.drawer` CSS
classes — no bespoke style sheets.

---

### R3 — Strong interactability

**Rule.** Every node is clickable AND keyboard-operable: `role="button"`, `tabIndex={0}`, Enter
and Space key handlers call `onSelect`. Selection opens a detail drawer showing `symbol`, `ref`
(as a live GitHub link via `sourceUrl`), `desc`, and `note`. Views offer subject switching (pill
tablist), sub-view switching (lens selector / schema / stats tabs), and param controls (e.g.
token slider for lens metrics). Cross-links between modes (Architecture drawer links to Component
mode for the implementation graph; Component drawer links to Data mode for token counts). Drawer
is sticky on scroll. Hover and focus affordances are clear (`:hover` surface lift, `:focus-visible`
3 px cyan outline).

**Acceptance check.** Keyboard navigation reaches every interactive control without a pointer.
Selection state is reflected in the drawer immediately. Cross-links open the correct mode and
pre-select the correct subject/block.

---

### R4 — Accessibility

**Rule.**
- `.skip-link` at the top of the document, leading to `#main-content`.
- `:focus-visible` outline ≥ 3 px on all interactive elements.
- ARIA roles on all composite widgets: `role="tablist"` on switcher nav, `role="tab"` on pills,
  `role="group"` on interactive SVG diagrams (not `role="img"` — SVG nodes are individually
  operable via `role="button"`).
- `prefers-reduced-motion` guards on **all** motion: flow-tick animation, hover transitions,
  drawer slide-in. Use `@media (prefers-reduced-motion: reduce)` to remove or freeze animations.

**Acceptance check.** Tab order traverses all interactive nodes; VoiceOver / NVDA announces
`aria-label` on diagram nodes; reduced-motion media query freezes tick animation.

---

### R5 — Data-driven contract

**Rule.** Each mode is defined by:
- An `index.json` listing available subjects (models / datasets / subsystems).
- One manifest JSON per subject containing all data the view needs to render.
- An optional registry JSON for cross-cutting metadata.
- One generic view component that is a pure reader of the manifest.
- One or more generator scripts under `scripts/` that produce the JSON from source of truth
  (repo files, HuggingFace configs, dataset samples, etc.).

All generators run through the repo `.venv` (`AGENTS.md` rule). Code references in manifests
are grounded to real `file:line` via symbol-grep (`scripts/_refs.py → resolve_line`). The SPA
never hard-codes architecture details; it renders whatever the manifest says.

**Acceptance check.** Delete all `public/data/` files, run `workflow.sh gen-data`, confirm the
SPA renders correctly without any code changes.

---

### R6 — Portability and deploy

**Rule.** All data and asset URLs are resolved via `import.meta.env.BASE_URL` using
`lib/assets.ts → dataUrl(path)`. The app ships to GitHub Pages under a sub-path. No absolute
`/` paths in `fetch()` calls or `<img src>` attributes.

**Acceptance check.** Build with `BASE_URL=/vllm/` (or equivalent sub-path), deploy, confirm
assets and data load without 404s.

---

### R7 — State model

**Rule.** React hooks only. No router (URL does not change on tab/subject switch). No global
store (Zustand, Redux, Context for non-UI state). Mode, subject, lens, selected block, drawer
open/closed — all local `useState` in the relevant component or its immediate parent.

**Acceptance check.** No import of `react-router`, `zustand`, `jotai`, `redux` in any source
file. Browser back/forward does not affect internal navigation state.

---

### R8 — Generality

**Rule.** Every mode supports switchable subjects:
- **Data** mode: datasets (FineWeb-edu, other corpora).
- **Component** mode: subsystem graphs (V1 engine, scheduler, sampler, …).
- **Architecture** mode: models (Qwen3-0.6B, Qwen3-8B, Qwen3-30B-A3B MoE, DeepSeek-V3 MLA-MoE).

Architecture conventions to preserve across all models:
- Bottom → top residual mainline.
- Branches tee off the mainline, run through a pre-norm + step cards inside a tinted panel,
  and merge back at a `+` node.
- Layer-variant brackets (dashed rounded rect) label each `LayerGroup`.
- Lens metrics (flow / shapes / compute / memory) reframe the same diagram without switching views.
- Total-vs-active parameter display for MoE models.
- GQA and MLA KV accounting in `blockTypes.ts → computeMetrics`.

**Acceptance check.** Adding a new model only requires adding an entry to `MODEL_LIST` in
`build_model_arch.py` and a fallback config in `FALLBACKS`; no React component changes needed.

## 3. The `ExplorerMode` Contract — **realized**

Implemented in [`src/explorer-kit/mode.ts`](src/explorer-kit/mode.ts) and consumed by
[`src/App.tsx`](src/App.tsx) as a typed `MODES` registry:

```ts
interface ExplorerModeProps { navigate: (id: string) => void }
interface ExplorerMode {
  id:       string            // 'data' | 'components' | 'architecture'
  label:    string            // family-switch nav label
  icon:     LucideIcon
  subtitle: string            // header subtitle for the active mode
  View:     ComponentType<ExplorerModeProps>
}
```

**Design decision — loading stays in each View.** Rather than hoist `loadIndex` /
`loadManifest` into a generic shell, each `View` remains its own index→manifest reader (it
already follows that pattern). The contract captures the *shared shape* and gives every mode a
`navigate(id)` prop — the general cross-link mechanism (R3) that replaced the bespoke
`onOpenArchitecture` callback. Adding a mode is now one `MODES` entry; no new conditional.

**Shared kit primitives (extracted, in [`src/explorer-kit/`](src/explorer-kit)):**

| Primitive | Responsibility |
|---|---|
| `AsyncBoundary` | `loading` / `error` / "run gen-data" empty states |
| `DetailDrawer` | sticky drawer with `symbol`, `ref` link, `desc`, `note` |
| `SubjectSwitcher` | `role="tablist"` pill row; fires `onChange(slug)` |
| `ViewTabs` | canonical pill tablist for sub-view / lens selection |

**Design decision — no `Toolbar` primitive.** A dedicated toolbar wrapper was evaluated and
intentionally *not* extracted: the three modes have differently shaped control rows, so a
one-size wrapper added coupling without payoff. Controls compose `SubjectSwitcher` / `ViewTabs`
/ `Slider` inside plain Tailwind utility rows instead.

## 4. Runbooks

### Add a new subject (model / dataset / subsystem)

1. **Architecture — new model:**
   a. Add `(slug, hf_id, family, label)` to `MODEL_LIST` in `build_model_arch.py`.
   b. Add a `FALLBACKS[slug]` dict with the offline config values.
   c. If the architecture family is new, add a template to `TEMPLATES` (reusing existing
      `_BlockDef` lists where possible).
   d. Run `workflow.sh gen-data` (uses repo `.venv`).
   e. Confirm `public/data/models/<slug>.json` and updated `index.json` are written.
   f. Open the SPA; confirm the model switcher shows the new entry and the diagram renders.
   g. Run the no-overflow audit (see Verification Checklist §5).

2. **Data — new dataset:**
   a. Add a generator script `scripts/build_<dataset>_sample.py` that writes
      `public/data/<dataset>/index.json` + `public/data/<dataset>/<slug>.json`.
   b. Add the generator call to `gen_data()` in `workflow.sh`.
   c. Add the new slug to `public/data/datasets/index.json` (or create it).
   d. Run `workflow.sh gen-data`; confirm files written.
   e. (Later phase) Add the dataset slug to `DataExplorer`'s `SubjectSwitcher`.

3. **Component — new subsystem graph:**
   a. Add the subsystem description and component list to `HACKERS_GUIDE.md` (or a linked
      supplementary doc in `hacks/`).
   b. Extend `build_component_manifest.py` to emit the new subsystem's node/edge list.
   c. Run `workflow.sh gen-data`; confirm `public/data/components.json` updated.
   d. (Later phase) Add the subsystem slug to `ComponentExplorer`'s `SubjectSwitcher`.

---

### Add a new mode

1. Add a `family` id to `App.tsx → FAMILIES` (id, label, icon).
2. Create `src/<mode>/<Mode>Explorer.tsx` importing `AsyncBoundary`, `SubjectSwitcher`,
   `DetailDrawer`, and `Toolbar` from `src/components/`.
3. Implement `loadIndex` and `loadManifest` using `fetchExplorerJson<T>` from `src/lib/fetch.ts`
   and `dataUrl` from `src/lib/assets.ts`.
4. Add a generator script `scripts/build_<mode>_manifest.py` that produces the index + per-subject
   manifests into `public/data/<mode>/`. Register it in `gen_data()` in `workflow.sh`.
5. Verify R1–R8:
   - Label budget (≤24 chars) and no-overflow audit.
   - Keyboard reachable; drawer works; cross-links wired.
   - `prefers-reduced-motion` guard on any new animation.
   - `dataUrl()` for all asset references.
   - No router / no global store imports.
6. Run `workflow.sh verify` and work through the full checklist.

## 5. Verification Checklist

Run these before declaring any generalization milestone complete:

### R1 — No-overflow and label-budget audit
```bash
# Regenerate manifests
cd /path/to/vllm
.venv/bin/python explorer/scripts/build_model_arch.py

# Audit: every label ≤ 24 chars; computed cardWidth fits every block
# (run the inline audit script; expected: "All blocks fit: YES")
.venv/bin/python - <<'EOF'
import json, math
from pathlib import Path
ADV=0.62; LABEL_PX=12; TAG_PX=7.5; METRIC_PX=9
PAD_L=16; PAD_R=14; TAG_GAP=12; COMFORT=16
CARD_W_MIN=240; MAIN_W_MIN=180
WORST="128×192×131072=24.6TB"
def cw(lbl,tag,m):
    ll=PAD_L+len(lbl)*LABEL_PX*ADV+(TAG_GAP+len(tag)*TAG_PX*ADV if tag else 0)+PAD_R
    ml=PAD_L+len(m)*METRIC_PX*ADV+PAD_R
    return math.ceil(max(ll,ml)+COMFORT)
ok=True
for jf in sorted(Path("explorer/public/data/models").glob("*.json")):
    if jf.name=="index.json": continue
    d=json.loads(jf.read_text())
    for b in d.get("prelude",[])+d.get("head",[]):
        w=cw(b["label"],None,WORST); req=max(MAIN_W_MIN,w)
        if req<w or len(b["label"])>24: print("FAIL",jf.name,b["label"]); ok=False
    for lg in d.get("layers",[]):
        for br in lg.get("branches",[]):
            for b in [br["preNorm"]]+br.get("steps",[]):
                w=cw(b["label"],b["kind"].upper(),WORST); req=max(CARD_W_MIN,w)
                if req<w or len(b["label"])>24: print("FAIL",jf.name,b["label"]); ok=False
print("All blocks fit:",ok)
EOF
```
